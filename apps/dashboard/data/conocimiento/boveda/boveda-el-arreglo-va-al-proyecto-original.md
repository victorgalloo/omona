- Cuando algo se rompe en una herramienta abierta, el arreglo se manda de regreso.
- En México y en LatAm usamos casi todo lo que se construye afuera. Toca aportar de regreso.
- Un PR abierto es mi prueba de trabajo: código, pruebas y revisión a la vista.
- Cómo se hace
  - El error sale del trabajo real, no de buscar qué aportar.
  - Primero el reporte con cómo reproducirlo. Después el arreglo con sus pruebas.
  - El estado de cada aporte se lee de GitHub. No escribo «fusionado» a mano.
  - Hasta el fondo
    - Si el arreglo lo hizo otra persona a partir de mi reporte, se dice así.
    - Un parche local se pierde en la siguiente actualización. Uno en el proyecto original le sirve a todos.
    - La lista viva está en [código abierto](https://omona.tech/open-source).
- Por qué
  - Cualquiera puede decir que sabe. Un PR se puede revisar.
  - Aprendo en público. Lo que sale mal también va a las notas.
